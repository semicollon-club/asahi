# 0009. 부원 간 격리를 만들지 않는다 — 지키지 못할 경계는 세우지 않는다

## 맥락

풀 하네스 4단계로 부원이 쓰게 될 경로가 바뀌었다. 얇은 워커에서는 도구마다 경로 게이트가
있었지만(`fs_*` → `allowed_dirs` + `WORKER_ROOTS`), 하네스 턴은 Claude Code 의 내장 도구가
**워커 계정(계정 B)의 권한 그대로** 돈다. 그래서 부원을 열면 한 부원의 세션이 다른 부원의
세션 전사를 읽을 수 있다 — 세션 폴더는 사람마다 나뉘지만 전부 같은 OS 계정의 것이다
(`risk-register.md` §10).

설계는 성능을 이유로 **부원별 OS 계정·컨테이너를 두지 않기로** 이미 정했다(설계 §5, 운영자
2026-09-05). 계정이 하나면 그 안에서 사람끼리 가리는 방법이 없다 — 세션은 자기가 만든 파일의
ACL 을 바꿀 수 있고, 내장 Bash 는 어떤 경로 게이트도 거치지 않는다.

`risk-register.md` §10 의 첫 판은 **부원을 열기 전에 셋 중 하나를 고르라**고 요구했다 —
(가) 계정 분리로 돌아가기, (나) 전사를 안 남기기(resume 포기 또는 봇이 대신 보관),
(다) 비공개가 아님을 명시하고 열기.

## 결정

**부원 간 격리를 만들지 않는다.** 부원끼리 서로의 하네스 세션 전사를 읽을 수 있다는 사실을
그대로 두고, 그 사실을 안내에 적는다.

공개 채널 대화가 아닌 예외 둘만 따로 처리한다.

1. **손님 DM 을 받지 않는다** — `decideRoute`(`agent/src/adapters/discord.ts`)가 등록된 손님의
   DM 에 `dm-declined` 를 돌려준다. 안내 한 줄만 나가고 대화 행도, LLM 턴도, 세션 전사도
   생기지 않는다. 소유자 DM 은 그대로다.
2. **소유자 전사는 개인 워커(계정 C)로 분리한다** — `resolveTurnWorker`(`core/agent.ts`)가
   소유자 DM 에 개인 워커를 먼저 찾고 없을 때만 공유 워커로 떨어지므로 코드 변경이 없다.
   미니PC 에 계정 하나와 예약 작업을 더해 개인 워커로 등록하는 운영 작업이다(게이트 항목).

## 근거

**셋 중 하나를 고르라는 요구 자체가 잘못 놓인 질문이었다.** 셋 다 "부원끼리는 서로에게
가려져야 한다"를 전제하는데, 이 프로젝트에서 그 전제가 성립한 적이 없다.

- 아사히는 **부원별 비서를 나눠 주는 물건이 아니라 동아리 작업을 총괄하는 하나의
  에이전트**다(운영자 2026-09-07). 개인 작업 공간을 약속한 적이 없다.
- 아사히가 도는 곳은 동아리 서버의 채널이고 **그 대화는 이미 부원 전부에게 보인다.** 전사가
  그 위에 더하는 것도 대부분 이미 열려 있다 — 그 턴에 읽힌 파일은 공용 워크스페이스의
  것이고, 손님에게는 봇 허브 MCP(DB 읽기 등)가 열리지 않는다(`core/profiles.ts` 의 `mcpHub`).
  남는 차이는 **스크롤을 올리는 대신 셸을 치는 것**뿐이다.

**그리고 완전하지 않은 격리는 없는 것보다 나쁠 수 있다**(운영자 2026-09-07). 이 리포에 실물
사례가 있다.

- **운영자는 경계가 있다고 믿고 확인을 멈춘다.** `risk-register.md` §12 가 그것이다 — 설계에
  "세션 계정에는 자격증명이 없다"고 적혀 있었기 때문에, 워커 계정이 봇 계정 홈에 **모든
  권한**을 갖고 있는 상태를 아무도 확인하지 않았다. 벽이 얕아서가 아니라 **실제보다 높다고
  적어서** 생긴 사고다.
- **사용자는 가려진다고 믿고 더 넣는다.** 디스코드 DM 창이 주는 "둘만 본다"는 신호가 그
  형태다 — 사람은 그 신호를 믿고 API 키·비밀번호를 붙여 넣는데, 실제로는 공용 기계에 전사가
  남는다. 그래서 안내문으로 신호를 정정하는 대신 **통로를 닫았다**(위 결정 1).

배제한 선택지:

- **(가) 부원별 OS 계정·컨테이너** — 성능을 이유로 2026-09-05 에 이미 배제됐고, 그 판단을
  뒤집을 새 근거가 없다.
- **(나) 전사를 안 남기기** — resume 을 포기하면 "지난 턴에 뭘 읽고 뭘 만들었나"가 사라져
  N1(디스코드에서 Claude Code 처럼)이 노리는 것을 정면으로 깎는다. 봇이 대신 보관하는 쪽은
  전사가 15~30MB 까지 가고(2026-09-06 실측) 턴마다 왕복해야 하는데, **그러고도 완전하지
  않다** — 세션 러너는 사람이 다르면 턴을 동시에 돌리므로 겹치는 동안 두 전사가 함께 디스크에
  있다. 값비싼 반쪽이다.
- **(다) 명시하고 열기** — 채택했다. 다만 "선택지 중 하나"가 아니라 **위 두 결정의 나머지
  절반**으로 다룬다. 가리지 않기로 한 이상 그 사실을 말하는 것이 의무다.

## 결과

- **부원끼리는 서로의 세션 전사를 읽을 수 있다.** 이것은 알려진 상태이지 고칠 대상이 아니다.
  `risk-register.md` §10 이 정본이고, 게이트의 "손님 안내 정정" 항목이 이 사실을 손님 눈에
  보이는 문구로 옮긴다 — *"아사히에게 한 말과 그 턴에 한 작업은 동아리 공용 기계에 남고 다른
  부원이 볼 수 있다. 비밀번호·API 키는 넣지 않는다."*
- **손님은 개인 기억을 가질 수 없다.** 기억 범위는 위치가 정하는데(`core/memoryScope.ts` —
  DM 이면 `user`, 서버면 `shared`) 손님에게 DM 이 없어졌기 때문이다. "부원별 비서가 아니다"와
  같은 방향이라 받아들인다.
- **손님 DM 페르소나 분기(`core/persona.ts`)는 도달하지 않는 코드가 됐다.** 정책을 되돌리면
  살아나므로 지우지 않고 주석으로 표시했다.
- **얕은 편의는 계속 만들 수 있다** — 다만 라벨을 정확히 붙인다. 예: §11 의 하네스 작업 폴더
  스코프는 코드 주석과 문서 양쪽에 *"OS 경계가 아니다 — 사고를 막을 뿐 공격을 막지 못한다"*
  를 함께 적는다. 이 ADR 이 금지하는 것은 얕은 벽이 아니라 **부풀린 라벨**이다.
- **이 결정을 되돌리려면** 전제를 먼저 뒤집어야 한다 — 아사히가 부원 개인의 작업 공간이
  된다면(예: 개인 프로젝트 지원) 위 근거의 첫 줄이 무너지고, 그때는 (가)로 돌아가는 것이
  유일하게 완전한 길이다. 반쪽 격리로는 이 문서가 기록한 두 실패가 그대로 재현된다.
