# 상황별 캐릭터 표정 이미지 출력

## 1. 배경 · 목표

리포 루트 `image/` 아래에 표정별로 정리된 캐릭터 이미지가 있다. 지금은 어디에서도 쓰이지 않는다.

Asahi 는 페르소나상 **이모지가 금지**돼 있고(`core/persona.ts`), 감정 표현 수단이 `…`과 뜸뿐이다.
표정 이미지가 그 자리를 대신하면, 무표정으로 말끝을 흐리던 캐릭터에 실제 표정이 붙는다.

**목표:** 모델이 답변에 표정 마커를 섞어 쓰면 봇이 해당 표정 이미지를 함께 보낸다.
**감정이 실제로 움직일 때만**, 모든 채널에서.

### 1.1 현재 자산

| 폴더 | 장수 |
|---|---|
| 기본 무표정 | 5 |
| 당황 | 5 |
| 멍함 | 5 |
| 빤히 응시 | 5 |
| 웃음 | 1 |
| 절망 | 3 |
| 졸림 | 4 |
| 혼란 | 5 |
| 홍조 | 5 |
| 화남 | 5 |

감정 이미지 총 43장. `임시/`(9장)는 옛 공유용 파일 보관소이므로 감정이 아니다 — 카탈로그에서 제외한다.

### 1.2 지금 구조가 막고 있는 것

| 제약 | 내용 |
|---|---|
| Railway 빌드 컨텍스트 | `agent/` 다. `image/` 는 리포 루트에 `agent/` 와 형제로 있어 **컨테이너에 들어가지 않는다**(`agent/Dockerfile` 주석 참고) |
| 디스코드 어댑터 | `send(channelRef, text)` 가 텍스트만 보낸다(`adapters/discord.ts:398`). 첨부·embed 경로가 없다 |

## 2. 확정된 결정

| # | 결정 | 선택 | 근거 |
|---|---|---|---|
| D1 | 이미지 저장 위치 | **Supabase Storage** | 이미지 추가·교체에 재배포가 필요 없다. 컨테이너·Railway 설정을 건드리지 않는다 |
| D2 | 봇의 신규 의존성 | **없음** | 업로드는 스크립트가 `fetch` 로 Storage API 직접 호출, 카탈로그는 기존 `pg`. `supabase-js` 를 들이지 않는다 |
| D3 | 모델의 선택 방식 | **응답 내 마커** `[표정:홍조]` | 도구 호출은 왕복이 한 번 더 생기고 모델이 의식해야 한다. 마커는 답변을 쓰는 흐름 안에서 나온다 |
| D4 | 전송 형태 | **embed** (`setImage`) | URL 을 텍스트에 넣으면 주소가 그대로 보인다. embed 는 이미지만 나온다 |
| D5 | 빈도 | **프롬프트 지침 + 어댑터 하드 상한** 두 겹 | 프롬프트만으로는 반드시 샌다 |
| D6 | 범위 | **전 채널**(소유자 DM·손님 DM·공개 서버) | 마스코트 성격상 어디서든 같은 캐릭터여야 한다 |
| D7 | 실패 처리 | **항상 텍스트는 발송** | 이미지 때문에 답변이 막히면 안 된다 |

### 2.1 기각한 안

| 안 | 기각 사유 |
|---|---|
| `image/` 를 `agent/` 로 옮겨 컨테이너에 COPY | 이미지 한 장 추가에 커밋+재배포가 필요하다. 메시지마다 700KB 를 디스코드에 다시 업로드한다 |
| 디스코드 CDN URL 을 미리 받아 저장 | 디스코드 첨부 URL 은 서명·만료가 붙어 장기 보관이 불가능하다 |
| 도구 호출(`send_image(감정)`) | 왕복 추가. 모델이 "도구를 써야지"라고 의식해야 해서 자연스러운 표정 표현이 안 된다 |

## 3. 저장 · 카탈로그

### 3.1 Supabase Storage

버킷 하나(`character-images`)에 `<감정>/<파일명>` 으로 올린다. 공개 읽기로 설정해
안정적인 공개 URL 을 쓴다 — 서명 URL 은 만료가 있어 카탈로그에 담을 수 없다.

### 3.2 카탈로그 테이블 (DDL 변경)

```sql
CREATE TABLE IF NOT EXISTS character_images (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  emotion TEXT NOT NULL,
  url TEXT NOT NULL,
  created_ts BIGINT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_character_images_emotion ON character_images(emotion);
```

`schema.ts` 가 부팅 시 `CREATE TABLE IF NOT EXISTS` 를 실행하므로 배포하면 자동 생성된다.
**이 프로젝트에서 처음으로 DDL 을 추가하는 변경이다** — 지금까지의 작업은 전부 기존 테이블을 재사용했다.

### 3.3 동기화 스크립트

`scripts/sync-images.mjs` 가 `image/` 를 순회한다.

- `임시` 등 감정이 아닌 폴더는 **무시 목록**으로 건너뛴다. 목록은 스크립트 상단 상수로 두어 추가가 쉽게 한다.
- 파일이 하나도 없는 폴더는 카탈로그에 넣지 않는다 — 모델이 없는 표정을 부르는 걸 막는다.
- 업로드 후 `character_images` 를 **통째로 갈아끼운다**(DELETE 후 INSERT). 삭제된 이미지가 카탈로그에 남지 않게 하기 위해서다.
- 필요한 환경변수: `DATABASE_URL`, `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`. `.env.example` 에 추가한다.

이미지를 추가·교체하면 이 스크립트만 다시 돌린다. 재배포는 필요 없다.

## 4. 마커

### 4.1 문법

```
[표정:홍조]
```

감정 이름은 폴더명 그대로다. 공백이 들어간 이름(`기본 무표정`, `빤히 응시`)도 그대로 쓴다.

### 4.2 파싱 규칙

`core/expressions.ts` 의 순수 함수로 분리한다. I/O 없음, 테스트 대상.

```ts
export type ParsedExpression = { text: string; emotion: string | null };
export function parseExpression(raw: string): ParsedExpression;
```

- 마커는 응답 **어디에든** 올 수 있다. 앞·중간·뒤 모두 허용한다.
- 마커가 여러 개면 **첫 번째만** 채택하고 나머지는 제거한다.
- 마커를 제거한 뒤 남는 공백을 정리한다(연속 공백·줄 끝 공백·앞뒤 공백).
- 마커만 있고 본문이 없으면 `text` 는 빈 문자열이 된다. 이 경우 어댑터는 이미지만 보낸다.
- 감정 이름이 카탈로그에 없으면 마커는 제거하되 이미지는 보내지 않는다(§6).

**가장 눈에 띄는 실패는 마커가 사용자에게 그대로 보이는 것이다.** 파싱을 순수 함수로 떼어낸
이유가 이것이고, 테스트로 못 박는다(§7).

## 5. 전송

`adapters/discord.ts` 의 `send(channelRef, text)` 를 확장해 이미지 URL 을 함께 받는다.

- 텍스트는 기존 `chunkMessage` 경로 그대로 보낸다.
- 이미지는 `EmbedBuilder().setImage(url)` 로 **마지막 청크와 함께** 보낸다. 별도 메시지로 보내면
  두 줄로 갈라져 어색하다.
- 텍스트가 비어 있으면 embed 만 보낸다.

같은 감정 폴더 안에서는 **무작위로 한 장** 고른다. 대화별로 직전에 쓴 URL 을 기억해 연속으로
같은 장이 나오지 않게 한다(폴더에 한 장뿐이면 그대로 쓴다 — `웃음` 이 현재 그렇다).

## 6. 빈도 제어 — 두 겹

### 6.1 프롬프트 (`core/persona.ts`)

감정 목록과 사용 지침을 시스템 프롬프트에 넣는다. 목록은 부팅 시 카탈로그에서 읽어 주입하므로,
폴더를 추가하면 코드 수정 없이 반영된다.

지침의 핵심은 **언제 쓰지 않는가**다.

- 감정이 실제로 움직일 때만 쓴다 — 놀람, 부끄러움, 어이없음, 졸림 같은 순간.
- 평범한 답변·작업 보고·정보 전달에는 붙이지 않는다.
- 매 답변마다 붙이지 않는다. 안 붙이는 게 기본이다.

### 6.2 어댑터 하드 상한

프롬프트 지침은 반드시 샌다. 어댑터가 대화별로 **최소 간격**을 강제한다.

- 같은 대화에서 직전 이미지 발송으로부터 **120초**(`EXPRESSION_MIN_INTERVAL_MS = 120_000`)가 지나지 않았으면
  마커를 무시하고 텍스트만 보낸다. 이 값은 상수로 두어 튜닝 가능하게 한다.
- 120초는 병리적 남발만 걸러내는 하한이다 — 모델이 지침대로 쓰면 애초에 이보다 드물게 나오므로,
  정상 동작을 막지 않으면서 "매 답변마다 표정" 같은 상태는 확실히 차단한다.
- 상태는 어댑터 메모리에 둔다(대화 ID → `{ 마지막 발송 시각, 마지막 URL }`). 마지막 URL 은 §5 의
  연속 중복 방지에 쓴다. 재배포로 초기화돼도 무해하다 — 최악이 이미지 한 장 더 나가는 것이다.

| `discordProgress.test.ts` 계열 (수정) | embed 가 마지막 청크와 함께 나가는지, 텍스트가 비면 embed 만 나가는지, 간격 상한이 걸리면 이미지 없이 텍스트만 나가는지 |
| `persona.test.ts` (수정) | 감정 목록이 프롬프트에 들어가는지, 카탈로그가 비면 표정 지침 자체가 빠지는지 |

동기화 스크립트는 유닛 테스트하지 않는다 — 실제 Storage 왕복이 본체이므로 수동 확인 항목으로 둔다(§9).

## 8. 실패 처리

| 상황 | 동작 |
|---|---|
| 카탈로그가 비어 있음 | 프롬프트에 표정 지침을 넣지 않는다. 마커가 와도 제거만 하고 텍스트 발송 |
| 모르는 감정 이름 | 마커 제거, 이미지 없음, 텍스트 정상 발송 |
| 카탈로그 조회 실패 | 이미지 없이 텍스트 발송. 오류는 로그만 |
| Storage URL 이 죽음 | 디스코드가 embed 를 못 그릴 뿐, 텍스트는 이미 나갔다 |
| 간격 상한에 걸림 | 마커 제거, 이미지 없음, 텍스트 정상 발송 |

**어느 경우에도 텍스트 답변은 나간다.**

## 9. 범위 밖 (YAGNI)

- WebP 변환·이미지 최적화 (현재 장당 평균 700KB. 장수가 늘면 그때)
- 감정 자동 추론(모델이 마커를 안 써도 문맥으로 붙이기)
- 사용자별 표정 선호·차단
- 애니메이션·연속 표정
- 이미지 생성

## 10. 알려진 한계

| # | 한계 | 비고 |
|---|---|---|
| L1 | 마커가 새어나갈 가능성 | 파싱 순수 함수 + 테스트로 최소화하되 0 은 아니다 |
| L2 | 모델이 지침을 무시하고 남발 | 어댑터 상한이 최종 방어선. 상한 자체는 튜닝 대상 |
| L3 | 카탈로그는 부팅 시 로드 | 스크립트로 이미지를 갱신해도 봇 재시작 전에는 새 감정이 프롬프트에 안 뜬다. URL 조회는 매번 DB 를 보므로 기존 감정의 이미지 교체는 즉시 반영된다 |
| L4 | Storage 는 공개 읽기 | URL 을 아는 사람은 누구나 볼 수 있다. 캐릭터 이미지라 문제되지 않는다 |
