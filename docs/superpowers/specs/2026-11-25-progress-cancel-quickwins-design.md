# 진행 표시 2.0 · 작업 취소 · 빠른 개선 넷 — 설계

[로드맵](../../status/ROADMAP.md)의 Now **N1**(진행 표시 2.0)·**N2**(작업 제어)와, 2026-11-25 운영 점검에서
나온 작은 개선 넷을 한 브랜치에 담는다. N1·N2 의 문제 정의·완료 기준은
[사용성 로드맵 근거 문서](./2026-09-22-usability-roadmap-design.md) §3.2 가 정본이고, 이 문서는 **어떻게**만 적는다.

## 1. 빠른 개선 넷

### 1.1 구독 인증 실패를 소유자에게 알린다

- **문제(2026-11-25 실측)**: 봇의 구독 토큰(`CLAUDE_CODE_OAUTH_TOKEN`)이 Anthropic 쪽에서 폐기돼 모든 턴이
  `401 OAuth access token has been revoked` 로 실패했다. 말을 건 사람마다 원문 오류만 받았고, 소유자에게 따로
  알리는 장치가 없어 누군가 직접 알려 주기 전까지 아무도 몰랐다(워커 부재 경보는 있지만 인증 실패는 없다).
- **결정**: `core/authFailure.ts` 의 `isAuthFailure(원문)` 가 업스트림 인증 실패 문구만 판정한다. Claude Code 가
  비대화 모드에서 바꿔 내는 문구("…does not have access to Claude…", "Please run /login")와 봇 프록시의 "구독 자격증명이
  없어요"(봇 `.env` 에 토큰이 없음)도 같은 실패로 본다(리뷰 반영). 프록시가 작업 토큰을 거부한 경우("작업 토큰…",
  `llmProxy.ts`)는 구독 문제가 아니므로 제외한다. `runConversationTurn` 의 실패
  결과·예외 두 갈래에서 판정해 (1) 사용자 안내를 "구독 인증 실패 — 운영자에게 알렸다"로 바꾸고 (2) 소유자 DM 에
  한 번 알린다. 알림은 **6시간에 한 번**(프로세스 메모리) — 매 턴 DM 이 쌓이면 정작 읽히지 않는다. 소유자 자신의
  DM 에서 난 실패는 그 자리 안내가 곧 알림이라 따로 보내지 않는다.
- **완료 기준**: 인증 실패 턴에서 소유자 DM 에 조치(토큰 재발급·봇 재시작)가 담긴 알림이 한 번 온다.

### 1.2 긴 답 분할이 코드블록을 깨지 않는다

- **문제**: `chunkMessage` 는 2000자 경계에서 줄바꿈 단위로 자를 뿐 코드블록(```` ``` ````)을 모른다. 블록 중간에서
  잘리면 앞 메시지는 블록이 닫히지 않고, 뒤 메시지는 코드가 본문으로 보인다.
- **결정**: 본문에 펜스가 있을 때만 여유분(24자)을 남기고 자른 뒤, 펜스가 열린 채 끝나는 조각은 닫고 다음 조각
  앞에 같은 여는 줄(언어 표기 포함, 길면 언어 생략)을 다시 붙인다. 펜스가 없는 본문은 지금과 **바이트 단위로
  같은** 결과를 낸다(기존 테스트가 그대로 지킨다).

### 1.3 답장 — 봇 메시지에 답장하면 부르고, 답장 대상을 문맥으로 싣는다

- **문제**: 일반 채널에서 봇의 메시지(정기 게시·알림)에 답장으로 물으면 반응하지 않는다(`detectBotMention` 이
  답장 자동멘션을 일부러 무시한다 — @everyone·역할 멘션과 같은 줄에 묶여 있었다). 답장으로 묻더라도 답장 대상
  메시지는 모델에 전달되지 않아 "이거 설명해줘"가 성립하지 않는다. 또 봇 자신의 멘션(`<@id>`)이 프롬프트와
  스레드 이름에 그대로 들어간다.
- **결정**: (1) **봇 메시지에 대한 핑이 켜진 답장**은 직접 멘션과 같이 부르는 것으로 본다 — @everyone·역할 멘션
  무시는 그대로다. discord.js 는 `mentions.repliedUser` 를 핑 여부와 무관하게 채우므로, 봇이 `mentions.users` 에도
  있을 때(= 핑)만 센다(`detectReplyToBot`, 리뷰 반영). 핑을 끈 답장은 남들끼리의 대화일 수 있어 부르지 않는다.
  (2) 처리하기로 정한 메시지가 같은 채널의 답장(`reference.type` 이 Default — 다른 채널 글인 전달은 제외)이면 대상을
  한 번 읽어 `[답장 대상(인용) · <신분> 이름: 내용 앞 500자]` 를 본문 앞에 붙인다. **인용은 신뢰할 수 없는 자료다**:
  평소 모델에 닿지 못하는 미등록자의 글도 소유자가 답장하면 소유자 턴에 들어간다. 그래서 한 줄로 펴고 대괄호를 바꿔
  프롬프트 구조(구분선·화자 표기)를 흉내 내지 못하게 하고, 신분(봇·운영자·부원·미등록)은 표시 이름이 아니라 어댑터가
  판정한 태그로 붙인다. (3) 봇 자신의 멘션은 본문과 스레드 이름에서 뺀다. 다른 사람의 멘션은 그대로 둔다 — 소유자가
  `@이름` 으로 부원을 가리키면 모델은 그 안의 숫자 ID 로 `manage_access` 를 부른다.

### 1.4 거절된 이미지도 알린다

- **문제**: 형식 미지원·5MB 초과·5장째 이상인 이미지는 아무 안내 없이 버려진다(`discord.ts` 의 이미지 `skipped`).
  파일 쪽은 이미 거절 사유를 `[파일 처리 실패: …]` 마커로 모델에 싣는다.
- **결정**: 이미지 거절 사유도 같은 `rejectedFiles` 로 나른다. 첨부 분류는 순수 함수 `sortAttachments` 로 뽑아
  테스트한다.

## 2. N1 — 진행 표시 2.0

- **(a) 판단 줄**: `progressFromMessage`(`core/sdkEvents.ts`)가 모델의 텍스트 블록을 `{ kind: "note", text }`
  (첫 줄·100자)로 내보낸다 — 도구 사이에서 모델이 "무엇을 보았고 그래서 무엇을 하기로 했는지"가 진행 표시에
  `판단: …` 한 줄로 남는다. 봇 자기 세션과 하네스 러너가 이 함수를 함께 쓰므로 두 경로가 한 번에 바뀐다.
  `isProgressUpdate` 가 `note` 를 받는다. 비어 있는 텍스트 블록은 예전처럼 `answering` 이다.
- **(b) 끝나도 남는 기록**: 턴이 끝나면 상태 메시지를 지우지 않고 `작업 기록 · N단계 · M분 S초` 머리줄 아래
  스포일러(`||…||`)로 접는다. 2000자 안에 최근 줄부터 담고 넘치면 `(앞 N줄 생략)` 을 적는다. 마지막 도구 뒤의
  판단 줄은 곧 최종 답의 첫 문장이므로 기록에서 뺀다. 줄 안의 `||` 는 스포일러를 끊지 않게 사이에 폭 없는 공백을
  넣는다. **도구를 한 번도 쓰지 않은 턴**(대부분의 짧은 대화)은 남길 것이 없으니 지금처럼 지운다. **기록에는 도구 결과의
  요약(출력 첫 줄)을 싣지 않는다**(리뷰 반영) — 진행 중에는 흘러가 사라지던 줄이 이제 공개 스레드에 영구히 남으므로,
  `.env` 를 읽은 턴이 그 값을 기록에 박지 않게 성패·도구 이름·소요만 남긴다(코어가 진행 이벤트에 기록용 줄 `record` 를
  따로 싣는다). 상태 메시지는 멘션 알림을 보내지 않는다(`allowedMentions: { parse: [] }`) — 판단 줄은 모델이 쓴 글이다.
  판단 줄은 assistant 메시지에서만 뽑는다 — user 메시지의 텍스트(서브에이전트 프롬프트·스킬 본문)는 모델의 판단이 아니다.
- **(c) 머리줄**: 진행 중에는 `처리 중 · N단계 · 경과 M분 S초`. N 은 도구 호출 수, 경과는 그 턴의 첫 진행
  이벤트부터. 오래 도는 도구(설치·빌드) 동안에도 경과가 흐르도록 상태 메시지가 있는 동안 15초마다 다시 그린다
  (디스코드 편집 한도 안이다). 마지막 진행 이벤트 뒤 35분(하네스 턴 상한 30분보다 길게)이 지나면 다시 그리기를 멈춘다 —
  종료 이벤트를 놓친 상태 메시지가 봇이 사는 내내 편집되지 않게 한다(리뷰 반영). 편집 800ms 스로틀은 그대로다.
- **배선**: 진행 이벤트(`ProgressEvent`)에 선택 필드 `kind` 를 싣는다 — 어댑터가 단계 수와 끝 판단 줄을 가리려면
  줄의 종류를 알아야 한다. 문자열 포맷은 지금처럼 코어(`formatProgress`)가 맡는다.

## 3. N2 — 작업 취소

- **수단 둘, 경로 하나**: 예약어 `/취소`·`/중지`·`/stop`(스레드·DM 안)과, 상태 메시지에 붙는 **중지 버튼**.
  버튼은 이 봇의 첫 디스코드 상호작용(`interactionCreate`)이다. 둘 다 코어의 `requestCancel(채널, 요청자)` 로 간다.
- **어디서 처리하는가**: 코어는 대화 채널별로 진행 중인 턴(`AbortController`·요청자)을 들고 있다. 예약어는
  **수신(ingest) 체인**에서 처리한다 — 턴 체인에 실으면 멈추려는 그 턴 뒤에 줄을 서서 의미가 없다.
- **권한**: 그 턴을 시킨 사람 또는 소유자. 공유 스레드에서 남의 작업을 멈추지 못하게 한다.
- **중단**: 봇 자기 세션은 SDK `query` 의 `abortController`, 하네스 턴은 `hub.startTurn().cancel()`(→ 러너의
  `turn.cancel` → 러너가 이미 갖고 있던 SDK 중단). 러너는 중단돼도 **그때까지의 세션 id 를 결과에 싣는다** —
  지금은 예외 갈래에서 세션 id 가 버려져 "취소 → 이어서"가 끊긴다(`remote/sessionRunner.ts`).
- **취소 뒤**: 세션을 저장해 다음 턴이 그 자리에서 이어받게 하고(PR #112 의 실패 턴 세션 보존과 같은 원리),
  대화 기록에 system 행을 남기고, `작업을 멈췄어요 …` 안내를 낸다. 진행 표시 기록(N1-b)이 "어디까지 했는지"다.
  멈춤이 결과와 엇갈려 성공 결과가 이미 왔으면 성공이 이긴다(봇 세션·러너 둘 다). 러너는 **사람이 멈춘 경우에만** 세션
  id 를 싣는다 — 다른 예외로 끝난 세션까지 저장하면 이어받을 수 없는 세션을 계속 resume 하려다 실패할 수 있다. 중단된
  세션이 이어받기를 거절하면(결과 없는 도구 호출 — `isBrokenSession`) 세션 없음과 같이 버리고 새 세션으로 다시 한다.
- **종료 이벤트는 반드시 나간다**: 종료 이벤트를 내기 전에 진행 중 등록을 풀고(그 틈의 `/취소` 가 끝난 턴에 진행 줄을
  남기지 않게), 안내의 DB 기록이 실패해도 이벤트는 낸다(`notify`·취소 마무리 — 안 내면 상태 메시지가 버튼을 단 채 남는다).
- **턴 도중 온 메시지**: 진행 중인 턴이 있으면 그 턴의 진행 표시에 `새 메시지는 지금 작업이 끝나면 이어서
  처리합니다` 를 한 줄 남긴다(조용히 다음 턴이 되던 것을 보이게 한다).
- **반응 순번 보호**: 어댑터는 턴을 시작시킨 메시지마다 👀 를 달고 턴 종료 이벤트마다 하나씩 ✅ 로 바꾼다
  (`pendingTriggers` FIFO). `/취소` 는 턴을 시작하지 않으므로 순번에 넣지 않고, 취소 응답(멈출 작업 없음·권한
  없음)은 상태를 끝내지 않는 새 이벤트 `side_notice` 로 보낸다 — 진행 중인 턴의 상태 메시지를 엉뚱하게 닫지 않는다.
  일반 채널에서 멘션과 함께 친 `/취소` 는 스레드를 만들지 않고 한 줄 안내만 한다. 같은 이유로 턴 바깥에서 나가던 다른
  알림(턴 도중의 이미지 실패 안내, 워커 부재 경보, PR 추적 알림)도 `side_notice` 로 옮겼다(리뷰 반영).
- **알려진 한계**: 멈춤은 모델을 멈출 뿐, 워커에서 이미 돌고 있던 원격 호출(`sh_exec` 등, 최대 120초)과 첨부 내려받기는
  끝까지 간다 — 안내 문구가 그 사실을 말한다. 턴이 한도 확인·예약을 지나 등록되기 전의 아주 이른 `/취소` 는 "멈출 작업이
  없어요" 가 된다. 둘 다 원격 호출 취소 프레임이 필요한 별도 작업이다.

## 4. 범위 밖

- 턴 도중 메시지를 진행 중인 세션에 끼워 넣기(조향) — 근거 문서 §3.2 가 배제했다.
- 슬래시(앱) 명령 등록 — 전역 등록·권한 설계가 따로 필요하다. 버튼은 등록 없이 동작한다.
- 로드맵 X4(마크다운이 경로를 깨뜨림) — 기록 줄도 같은 한계를 그대로 갖는다.

## 5. 호환·배포

봇과 워커는 같은 `production` 을 따르지만 갱신 시각이 몇 분 어긋날 수 있다. 새 워커가 보낸 `note` 를 옛 봇은
`isProgressUpdate` 에서 버리고(표시만 빠짐), 옛 워커가 보낸 `answering` 은 새 봇이 그대로 받는다. 실패 결과의
`sessionId` 는 프로토콜이 이미 허용한다(`remote/protocol.ts`). 버튼에는 봇 권한·인텐트 추가가 필요 없다.

## 6. 검증

- 유닛: `isAuthFailure`·알림 주기, 펜스 분할, 답장 판정·인용·멘션 제거, 첨부 분류, `note` 추출·형식, 머리줄·기록
  형식(2000자·`||`·끝 판단 줄), 취소 명령 파싱, 코어 취소 흐름(요청자·소유자·권한 없음·멈출 것 없음·세션 저장·
  도중 메시지 안내·인증 실패 알림), 하네스 취소(`cancel()` 호출·`cancelled`), 러너의 중단 시 세션 id.
- **이음매 뒤(스모크로만 확인)**: 실제 SDK 의 `abortController` 중단(봇 자기 세션 — `agent.test.ts` 는 SDK 를
  부르지 않는다), 실제 버튼 클릭, 실제 401. 항목은 [스모크 테스트](../../../deploy/smoke-test.md)에 더한다.
